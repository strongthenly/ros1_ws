# FUEL + SUPER 联调 · 测试流程（照做版）

> 环境：Windows 11 + AirSim(UE4.27) + WSL2(ros1-twin, Ubuntu 20.04 / ROS Noetic)
> 三个脚本：`~/super_explore_all.sh`(启动) · `~/super_explore_stop.sh`(停止) · `~/twin_livo_fast.sh`(底层链路，被启动脚本调用)

---

## 阶段 0 · 前置（只做一次）

**① Windows 侧：打开 AirSim 场景并点 ▶ Play**

```
E:\AirSim\Unreal\Environments\Blocks\Blocks.uproject  →  双击 → Unreal 编辑器 → 点 ▶
```
> ⚠️ 本机没有打包版 `Blocks.exe`，**必须手动 Play**，这是唯一需要手的步骤。
> 判断成功：Unreal 视口变成可交互的游戏画面（不是编辑器视口）。

**② WSL 侧：确认工作区**

```bash
wsl -d ros1-twin -u liyan          # 从 Windows 进入 WSL
cd ~ && ls -d fuel_ws super_sim_ws twin_ws
# 三个目录都在即可
```

## 阶段 1 · 清场（每次实验前必做）

```bash
bash ~/super_explore_stop.sh --all
```

**预期**：8 步依次执行，结尾是

```
已停: SUPER FUEL 仲裁器 MAVROS FAST-LIVO2 桥 RViz PX4 master
残留检查:
  [OK] fsm_node 已停
  [OK] super_to_px4_bridge 已停
  [OK] exploration_node 已停
  [OK] traj_server 已停
  [OK] goal_arbiter 已停
  [OK] mavros 已停
  [OK] fastlivo_mapping 已停
```
> 若某项显示 `[!] 仍在跑` → 手动 `pkill -9 -f <名字>` 后重来。
> **为什么要清场**：master 里会留"僵尸注册"（进程已死但话题还挂在发布者列表），会污染后面的自检。

## 阶段 2 · 启动

```bash
bash ~/super_explore_all.sh 1
```

- **`1` = 退出时保存建图 PCD**（`0` 或不传 = 不保存）
- 想先核对参数：`bash ~/super_explore_all.sh 1 --print-params`
  ```
  PARAMS pcd=1 dry=no super=1 fuel=1 trig=no min=3.0
  ```
- 首次联调建议加 `--dry-run`（仲裁器只打印不发布，飞机不动）

**7 步会依次输出**，每步都有硬检查，任何一步失败会**立即中止并指出原因**：

| 步骤 | 做什么 | 通过判据 |
|---|---|---|
| 1/7 | twin 链路（FAST-LIVO2） | `OK 4560 已连接` + `OK /clock 在走` + `OK 14610 在监听`（或 `OK 14610 已开（自动）`） |
| 2/7 | PX4 专用 MAVLink | `[OK] 14610 已在监听` —— 没开会**自动**向 pxh 发 `mavlink start` 并重试 |
| 3/7 | MAVROS | `[OK] MAVROS 已连接 FCU` |
| 4/7 | SUPER（仿真配置） | 日志出现 `Load param rog_map/...`、`Wait for goal.` |
| 5/7 | FUEL（改道输出） | `rostopic info /planning/pos_cmd` 的 Publishers **只有 `/fsm_node`** |
| 6/7 | 目标仲裁器 | 日志出现 `[arbiter] in=/exploration_goal out=/waypoint_goal` |
| 7/7 | 链路自检 + 触发 | 三个话题的发布/订阅关系正确 |

## 阶段 3 · 逐项自检（启动完成后，另开一个 WSL 终端）

```bash
export ROS_MASTER_URI=http://127.0.0.1:11311

# 3.1 进程存活
for p in fsm_node super_to_px4_bridge exploration_node traj_server goal_arbiter fastlivo_mapping mavros; do
  printf "%-22s %s\n" "$p" "$(pgrep -f $p | wc -l)"
done
```
**预期**：每项 ≥ 1。（`exploration_node`/`traj_server` 由 FUEL 的 roslaunch 拉起）

```bash
# 3.2 ⭐ 防抢控制（最关键的一项）
rostopic info /planning/pos_cmd | grep -A5 Publishers
```
**预期**：Publishers 里**只有 `/fsm_node`**。
> 若出现 `/traj_server` → FUEL 改道没生效（僵尸注册或 `fuel_cmd_topic` 没传）；
> 若一个都没有 → SUPER 没在出轨迹。

```bash
# 3.3 目标通道
rostopic info /exploration_goal    # Publishers: /exploration_node   Subscribers: /goal_arbiter
rostopic info /waypoint_goal       # Publishers: /goal_arbiter      Subscribers: /fsm_node
```
**预期**：四条关系都要对上（FUEL 发 → 仲裁器 → SUPER 收）。

```bash
# 3.4 数据流频率
for t in /cloud_registered /mavros/local_position/odom /clock; do
  echo "--- $t"; timeout 6 rostopic hz $t 2>/dev/null | grep average
done
```
**预期**：
| 话题 | 预期频率 |
|---|---|
| `/cloud_registered` | ~10 Hz |
| `/mavros/local_position/odom` | ≥ 50 Hz（**没有 = PX4 链路没通**） |
| `/clock` | 在走（**不动 = 仿真冻结**） |

## 阶段 4 · 触发探索

FUEL 的 FSM 需要收到**高度 ≥ -0.1** 的触发点（不是自动开始的）。

```bash
python3 - <<'EOF'
import rospy
from geometry_msgs.msg import PoseStamped
rospy.init_node('trigger_once')
p = rospy.Publisher('/move_base_simple/goal', PoseStamped, queue_size=1)
rospy.sleep(1.0)
m = PoseStamped()
m.header.frame_id = 'world'
m.pose.position.x, m.pose.position.y, m.pose.position.z = 0.0, 0.0, 1.0
m.pose.orientation.w = 1.0
p.publish(m)
rospy.sleep(0.5)
print("trigger sent")
EOF
```
> 用 Python 而不是 `rostopic pub` —— 后者的 YAML 引号在 WSL/PowerShell 里容易被破坏。

## 阶段 5 · 观察闭环

**开四个终端分别盯：**

```bash
tail -f /tmp/super_fsm.log      # SUPER 状态机
tail -f /tmp/super_bridge.log   # 控制桥（看 setpoint / OFFBOARD）
tail -f /tmp/fuel_real_super.log # FUEL（看 Next view / Cost mat）
tail -f /tmp/goal_arbiter.log   # 仲裁器（看 >>> 放行目标 ... | 原因: ...）
```

**成功闭环的日志长这样**（按顺序出现）：

```
# FUEL 侧
[FUEL] Next view: 12.3, 4.5, 1.2          ← 决定"去哪"
# 仲裁器
[arbiter] FUEL 候选目标: (12.30, 4.50, 1.20)
[arbiter] >>> 放行目标 (12.30, 4.50, 1.20) | 原因: 冷启动（无当前目标）
# SUPER 侧
[Fsm] Get goal at 12.375 4.575 1.125      ← 收到（注意会吸附到栅格中心，偏移 0.075=resolution/2）
```

**同时确认飞机真的在动**：
```bash
rostopic echo /mavros/local_position/pose/pose/position
```

**⚠️ 必须手动切入 OFFBOARD**：PX4 出于安全不会自动进 OFFBOARD，需要用遥控器/地面站切模式（bridge 日志会停在 `Waiting for OFFBOARD mode engagement (manual switch required)...`）。

## 阶段 6 · 停止（PCD 自动归档）

```bash
bash ~/super_explore_stop.sh
```

**预期**（第 5 步是关键）：

```
[stop] [5/8] 停 FAST-LIVO2（PCD保存=开）...
[stop]       已发 SIGINT，等它保存 PCD 并退出（最多 25s）...
[stop]       [OK] 已退出
[stop]       PCD 目录: /home/liyan/twin_ws/src/FAST-LIVO2/Log/pcd  (本次归档 3 个文件)
        116592093 B  all_raw_points_20260922_204530.pcd
            27354 B  lidar_poses_20260922_204530.txt
```

**⭐ 时间戳归档规则**：
- PCD 保存完后，脚本把**裸名**文件改成 `名字_YYYYMMDD_HHMMSS.扩展名`
- 时间戳取**文件自身的 mtime**，所以**历史上遗留的裸名文件也会被一并归档**
- **已带时间戳的不会再被改名**（可反复运行，幂等）
- 双保险：`twin_livo_fast.sh` 在**启动 FAST-LIVO2 之前**也会做一次归档（防 `kill -9` 导致停止脚本没跑到）

**⚠️ 绝对不要用 `kill -9` 关 FAST-LIVO2** —— 那样不会触发 savePCD，本次点云全部丢失。
需要快速关（放弃本次 PCD）时才用 `bash ~/super_explore_stop.sh --no-save`。

## 阶段 7 · 验证 PCD 产物

```bash
ls -lht ~/twin_ws/src/FAST-LIVO2/Log/pcd/
```
**预期**：每次实验一组文件，互不覆盖
```
all_raw_points_20260922_204530.pcd           ← 原始点云（大，百 MB 级）
all_downsampled_points_20260922_204530.pcd   ← 抽稀点云
lidar_poses_20260922_204530.txt              ← 雷达轨迹
```

**快速体检点云**（不装 ROS，用 numpy 读）：
```bash
python3 - <<'EOF'
import numpy as np, glob
f = sorted(glob.glob("/home/liyan/twin_ws/src/FAST-LIVO2/Log/pcd/all_raw_points_*.pcd"))[-1]
print("文件:", f)
raw = open(f, 'rb').read()
i = raw.find(b'DATA binary\n') + len(b'DATA binary\n')
pts = np.frombuffer(raw[i:], dtype=np.float32).reshape(-1, 4)
print("点数:", len(pts))
print("X/Y/Z 最小:", pts[:, :3].min(0))
print("X/Y/Z 最大:", pts[:, :3].max(0))
EOF
```
**判据**：点数应与「飞行时长 × 点数率」量级相符；X/Y 范围应覆盖你规划的区域。
若范围只有几米 → 定位失败或飞机没真正飞起来。

## 故障速查

| 现象 | 真因 | 处理 |
|---|---|---|
| `[X] 14610 未监听` + FATAL | 端口判据用错协议（14610 是 **UDP**，`ss -tln` 查不到）—— **已修复** | 现在用 `port_open()` 多口径（`-tuln`/`-uln`/`-tln`）+ PX4 日志兜底 |
| pxh 里 `Maximum MAVLink instance count of 4 reached` | 重复发过 `mavlink start` | 已修：检测到已开就不再重发；真要手动看 `mavlink status` |
| `[SUPER] No odom, force return` 刷屏 | MAVROS 没连 FCU（14610 通的但 MAVROS 没起/没连上） | `tail /tmp/mavros_super.log`；PX4 重启后**必须重开 MAVROS** |
| `/clock` 不动 | PX4 未连 AirSim / AirSim 没 Play | 确认 ▶ 已点；`ss -tn \| grep 4560` |
| 话题有 2 个发布者 | 上次残留的僵尸注册 | `bash ~/super_explore_stop.sh --all` 后重启 |
| FUEL 日志 0 字节 | launch 没起来 | 直接 `tail -30 /tmp/fuel_real_super.log`；多半是上游链路检查未过 |
| PX4 退出且 tmux 会话消失 | tmux server 死了 | 已改 `remain-on-exit`，现在会话会保留，`tmux capture-pane -p -t px4` 看死因 |
